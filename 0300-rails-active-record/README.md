# Active Record 課題：映画の座席予約

以下の要件を満たす映画予約アプリを作成してください。要件から必要なデータと関係を考え、スキーマ設計と Rails アプリケーションの実装を行います。モデル名、テーブルの分け方、カラム、関連は自分で設計してください。

## 取り組む際の注意

この課題は、コーディングエージェントを使用せずに実装してください。実装内容と、データの持ち方を選んだ理由を口頭で説明できる程度まで理解して進めることをおすすめします。

## 要件

### 映画・上映・座席

- 映画館は1館、スクリーンは1つとします。
- 映画のタイトルと上映時間（分）を登録できます。上映時間は正の整数です。
- 同じ映画を異なる日時に上映できます。
- 上映日時と上映する映画を確認できます。
- 上映回ごとに1席あたりの料金を円単位で設定できます。料金は0円以上の整数とし、税・割引の計算は今回扱いません。
- 座席には「A-1」「A-2」など、スクリーン内で重複しない番号があります。
- 映画、上映スケジュール、座席は初期データとして登録できれば十分です。これらの管理画面は必須ではありません。

### 予約

- 利用者は上映回を選び、その回の空席を確認できます。
- 名前とメールアドレスを入力し、同じ上映回の空席を1席以上選んで、まとめて予約できます。
- 1席でも確保できない場合は、その申し込みのすべての予約を取り消します。一部の座席だけ予約された状態を残してはいけません。
- 座席を選んでいない申し込みや、同じ座席を重複して選んだ申し込みは受け付けません。
- 名前・メールアドレスが未入力、またはメールアドレスの形式が不正な場合は予約できず、画面に理由が表示されます。
- 同じ上映回の同じ座席は、複数人が同時に操作しても二重予約できません。
- 同じ座席でも、別の上映回なら予約できます。
- 上映開始時刻以降は、新規予約とキャンセルができません。
- 予約成功時には、上映内容と座席、予約内容を確認できる画面を表示します。
- 予約が失敗した場合は、不完全な予約データを残さず、再操作できるようにします。

### 請求

- 予約時に、その申し込み全体に対する未払いの請求を1件作成します。外部サービスへの決済処理は不要です。
- 請求額は、予約時点の1席あたり料金と予約席数からアプリ側で計算します。利用者から送られた金額をそのまま採用してはいけません。
- 予約確認画面で、予約席、予約時の単価、請求額、請求の状態を確認できます。
- 上映回の料金が後から変更されても、作成済みの請求金額は変わりません。
- 座席の確保と請求の作成は、すべて成功する場合だけ確定します。途中の座席確保や請求作成に失敗した場合、申し込み全体を取り消し、座席も請求も残してはいけません。

### キャンセル

- 予約時に発行された確認用リンクから、自分の予約を確認・キャンセルできます。ログインやメール送信は不要です。
- 他の予約を連番などから簡単に参照・キャンセルできないようにしてください。
- キャンセルした座席は、その上映回で再予約できます。
- キャンセルは申し込み全体を対象とし、まとめて予約したすべての座席を解放します。一部の座席だけのキャンセルは今回の対象外です。
- 予約をキャンセルすると、請求も取り消し済みになります。座席だけ解放されて請求が有効な状態を残してはいけません。請求の履歴は残します。
- キャンセル済みの予約も、履歴として確認できます。
- 同じ確認用リンクからキャンセルを繰り返しても、ほかの予約に影響しません。

## 作る範囲

Rails と Active Record を使い、ブラウザから上映回の選択、空席確認、予約、予約・請求の確認、キャンセルができるアプリを作成します。データベースには Docker Compose で起動する PostgreSQL を使用します。画面デザインは自由です。外部決済、支払い処理、税・割引、会員登録、外部 API 連携、複数スクリーンへの対応は今回の対象外です。

PostgreSQL の起動と日本語を使った `psql` の操作は、[PostgreSQL のセットアップと操作](POSTGRESQL.md)を参照してください。
